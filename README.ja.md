# voice-browser 日本語版 — 声でブラウザを動かす

声で本物のブラウザ（Chromium）を操作する Node アプリです。話している途中の言葉を少しずつ AI に渡すので、言い終わる前に動き出すこともあります。
このリポジトリは [moritzkremb/jev-voice-browser](https://github.com/moritzkremb/jev-voice-browser) の Fork で、**`feature/japanese` ブランチで日本語に対応**しています（英語もそのまま使えます）。

- 判断するのは TypeSafe の **Jev**（`jev-1.13.0`）。文章は作らず、「何をしたいか」「どれを押すか」「言い終えたか」などを確率で答えるだけです
- 検索語や入力する文字は、コードが話した言葉から切り出します。Jev はその候補から選ぶだけなので、言った言葉がそのまま使われます
- 1 回の判断は約 300ms、費用は約 0.0002 ドルです

英語の詳しい説明（仕組み・判断の流れ・ファイル構成）は [README.md](README.md) にあります。

## 必要なもの

- **Node.js 20 以上**（22 で確認）と npm
- **Chrome または Edge**（マイクの音声認識に使います。Firefox・Safari では動きません）
- **TypeSafe の API キー**（[TypeSafe のコンソール](https://console.typesafe.ai/keys)で作ります。使った分だけ料金がかかります）
- マイク（無くても、画面の入力欄に文字で打てば試せます）

## インストール

```bash
git clone -b feature/japanese https://github.com/harutpo/jev-voice-browser.git
cd jev-voice-browser
npm install
npx playwright install chromium
```

次に、API キーを書くファイルを作ります。

```bash
# macOS / Linux
cp .env.example .env
```

```powershell
# Windows（PowerShell）
Copy-Item .env.example .env
```

`.env` を開き、`TYPESAFE_API_KEY=` の後ろに自分の API キーを書きます。`.env` は git に入りません。キーを読むのは手元の Node だけで、ブラウザの画面には渡りません。

## 起動（日本語モード）

```bash
node --env-file=.env src/server.js --lang ja
```

- macOS / Linux では `VB_LANG=ja ./run.sh` でも起動できます（Windows では `run.sh` が使えないので上のコマンドを使います）
- 起動すると、**操作される Chromium のウィンドウ**が別に開きます

1. **いつもの Chrome（または Edge）で http://localhost:8787 を開きます**（操作用の画面）
2. **Start mic** を押し、マイクを許可します
3. 話しかけると、もう一つの Chromium のウィンドウが動きます。操作用の画面には、AI の判断（確率のバー・かかった時間・費用）がその場で出ます

マイクを使わないときは、操作用の画面の入力欄に文字を打って Enter で試せます。

## 話しかけ方の例

| こう言うと | こうなる |
| --- | --- |
| 「ウィキペディアを開いて」「ヤフーに行って」「example ドット コム を開いて」 | そのサイトへ移動（日本語版: ja.wikipedia.org / amazon.co.jp / google.co.jp / yahoo.co.jp） |
| 「猫を検索して」「アラン・チューリングについて調べて」 | ページに検索ボックスがあればそこで、なければ DuckDuckGo で検索。検索語には「猫」だけが入る |
| 「ユーチューブでローファイを検索して」 | そのサイトの中で検索 |
| 「ログインをクリック」「2番目のリンクを開いて」 | 押す。どれか迷うときは番号のバッジが出るので「2番目」「二つ目」「最初」と答える |
| 「検索ボックスにこんにちはと入力して」 | その言葉をそのまま入力 |
| 「少し下にスクロール」「一番下まで」「前のページに戻って」「新しいタブを開いて」 | スクロール・戻る・タブ |
| 「注文を確定するをクリック」 | 取り消せない操作なので、「確定」か「キャンセル」と言うまで待つ |
| 「今日のお昼どうしようかな」 | ブラウザへの指示ではないので何もしない |

## 日本語対応で変えたこと

- **「言い終えたか」の判定だけ日本語向けに書き直しました。** 日本語は動詞が最後に来るので、「〜を」「〜に」で止まったときや、名詞・サイト名だけのときは待ちます。「開いて」「検索して」などの動詞で終わったら動きます
- Jev への質問文は英語のまま使い、日本語の例文を足しました。事前の試しでは、英語の質問文のままでも日本語の指示の意図を 13 問すべて当てました
- 検索語・入力する文字の切り出しは、「〜を検索して」「〜と入力して」などの助詞・語尾のルールで行い、足りないところは `Intl.Segmenter`（単語の区切り）で補います
- 「2番目」「二つ目」などの番号、「ドット コム」と読んだ URL、「検索」と書かれた検索ボックス、`.co.jp` のサイトにも対応しました
- 英語か日本語かは `--lang` で切り替えます（処理を分けているのは `src/lang.js`）

確かめた結果（2026 年 9 月）: 日本語の統合テスト 24/24（平均 約 300ms）、英語の統合テスト 27/27（これまでどおり）、実際のサイトでの日本語デモ 10/10。

```bash
npm test                                   # ユニットテスト（通信なし）
VB_LANG=ja npm run test:integration        # 日本語の統合テスト（Jev を実際に呼ぶので少し費用がかかる）
npm run demo:ci -- --lang ja               # 実際のサイトで日本語デモ（ウィンドウなし）
```

## 気をつけること

- **音声認識はブラウザの Web Speech API を使うので、声は Google に送られます**
- 実際のマイクでの日本語は、まだ十分に試していません。音声認識がかなを漢字に書き換える途中で判断が揺れ、「一息で 2 つの指示」がうまくいかないことがあります
- 操作用の画面は `127.0.0.1` でしか待ち受けません。この画面に届く人は誰でもブラウザを動かせて、API の料金も使えるので、`--host 0.0.0.0` は信頼できるネットワークだけで使ってください
- 操作される Chromium は `.browser-profile/` にログイン状態などを残します。聞き間違いで押されて困るアカウント（買い物・送金など）には、ここでログインしないでください。取り消せない操作の前には確認がありますが、あくまで補助です
- 押せるのは画面の上のほうの要素（最大 100 個）です。下のほうの要素は、先にスクロールしてから指示してください。iframe の中は見えません
- 一部のサイトは、自動操作を防ぐ仕組みで表示されないことがあります
